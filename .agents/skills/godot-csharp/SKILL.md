# Godot 4 — C# (.NET)

## When to use this skill

- **Scripts**: `partial class` with `Godot` namespace, `Node2D`, `CharacterBody3D`, etc.; lifecycle `Ready()`, `_Process(double delta)` (Godot 4 C# uses underscore-prefixed overrides matching the engine).
- **Signals**: `[Signal]` delegate, `EmitSignal`, `Callable.From`, connecting with type-safe handlers where possible.
- **Project files**: `.csproj` generated by Godot; **do not hand-edit** complex MSBuild logic unless the repo already does—prefer editor export options and `Directory.Build.props` patterns if documented in the project.
- **Async**: `await ToSignal(...)` patterns; avoid blocking the main thread with synchronous waits on game logic.

## Principles

- Match **existing** C# style in the repo (nullable reference types, file-scoped namespaces, etc.).
- Prefer **Godot collections and types** at boundaries (e.g. `Godot.Collections.Array`) when interoping with engine APIs that expect them.
- Keep hot paths **allocation-aware**; pooling may matter more than in typical GDScript prototypes.

## GDScript vs C#

- Do not mix languages in one class hierarchy; **pick the language the scene’s root script uses** and follow project conventions for tool scripts and autoloads.
